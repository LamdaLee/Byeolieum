## 서버 및 비용 경계

`GET /api/ideas`는 설정 상태만 공개. `POST`는 같은 출처 JSON, 8KB 이하, 카드 2~5개로 제한. OpenAI 키는 서버 환경변수만 읽는다. 고정 OpenAI HTTPS endpoint를 쓰며 임의 URL은 받지 않는다. 20초 타임아웃, 응답 구조·원본 근거 검증, 인스턴스 IP별 분당 3회 요청 제한. 분산 환경의 전역 quota나 인증 기능은 미구현이다. 키 설정 전 AI 결과를 생성했다고 표현하지 않는다.

프로젝트 기록은 브라우저에만 저장하나 AI 요청 시 선택 카드는 서버와 OpenAI에 전달된다. 데이터 정책은 OpenAI에도 적용된다. 운영 키는 Vercel 설정에서 공급한다. 실제 공급자 응답과 교육 효과는 실사용 검증이 필요하다.

## 이번 범위 밖

로그인, 계정 동기화, 협업, 결제, 자동 코딩/배포, JSON 파일 가져오기. API 키 없이도 기본 흐름을 완료할 수 있다. 보관함은 `byeolieum-library-v1`로 현재 작업과 분리해 저장한다. 다른 탭의 동시 편집은 지원하지 않는다.

## 계정 저장 확장

Google의 Supabase PKCE와 Kakao/Naver 서버 OAuth 연결을 제공한다. 게스트 작업은 그대로 보존하고 사용자가 가져오기를 선택해야 계정에 저장한다. 현재 작업과 보관함/실험 기록 전체를 사용자 UUID별 작업 공간으로 저장하며 RLS로 격리한다. 다른 기기 저장과 충돌하면 자동 덮어쓰기를 중단한다. 로그인·동기화는 API 비용을 발생시키는 AI 호출과 분리한다. Naver는 네이버 회원 ID를 검증한 뒤 비공개 사용자 매핑으로 Supabase UUID를 재사용한다. 제공자 사이의 자동 계정 합치기, 계정 삭제, JSON 가져오기, 협업 공유는 후속 범위다.

카카오는 회원 ID만 사용하며 이메일·사진·닉네임 동의 scope를 요청하지 않는다. 개인 정보 대신 내부 비공개 ID 매핑과 Supabase 인증 UUID로 계정 저장을 유지한다.
